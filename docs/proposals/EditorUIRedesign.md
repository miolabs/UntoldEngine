# Editor UI redesign: implementation plan

**Status:** Draft 3 (2026-09-19). Planning only; no code written. Draft 2 reordered delivery at the user's direction into three phases by engine dependency: first everything the engine supports today, built around Object mode (place objects, move around, change their properties in the Inspector); then the small engine additions; last the features that need engine refactors, Edit mode and animation among them (§6). Draft 3 adds the user's requirement that every area of the window is dockable, can change position, is resizable and can be hidden: the layout shell becomes a docking system with the mockup as its default layout (D8, D17, D18, stage 1.3). Decisions D1 to D18 (§5) are open.
**Inputs:** the design handoff, copied next to this file: `EditorUIRedesign/UNTOLD_EDITOR_UI_SPEC.md` (layout, sizes, colors, behaviour) and `EditorUIRedesign/images/01..06` (the six screens). The interactive mockup `Untold Editor.dc.html` that the spec refers to was not in the delivered zip; the six screenshots and the spec are the source of truth here.
**Scope:** `UntoldEditor` for every stage of phase 1. `UntoldEngine` for the small public APIs of phase 2 (§4). Mesh editing, painting, property keyframes, orthographic projection and the visionOS volume preview are engine features, not UI, and form phase 3.
**Baseline:** editor `develop` @ `ca76b8c` (v0.19.1; the miolabs fork is upstream `develop` plus the fork-only twins work, upstream has nothing newer today); engine `develop` @ `4be11087`; Xcode 27.0, Swift 6.4, deployment target macOS 14.
**Repos:** `miolabs/UntoldEditor` and `miolabs/UntoldEngine` for the work; one pull request per stage to `untoldengine/UntoldEditor` (§7).

## 1. The ask

Bring the editor window to the mockups: a toolbar in the title bar (project chip, undo/redo/history, play/pause/step, build target, search everywhere), a hierarchy with eye and lock columns, a scene tab strip, a viewport tool header (interaction mode, select/move/rotate/scale, world/local, snap, shading, projection, camera speed), viewport overlays (mode badge, stats, navigation gizmo, hint chips, selection rectangle), a resizable bottom dock with an asset grid/list, a console with filter chips and a source column, a new Timeline, an Inspector with an entity header, component sections and a Material section, and a status bar. Plus the state behind them: interaction modes, snapping, a build target, persisted layout.

Priority, stated by the user on 2026-09-19: the level designer's first need is Object mode, placing objects, moving around them and changing their properties in the Inspector, with hiding an entity as a key operation. Modifying the objects themselves (Edit mode) is the second most valuable thing, but it is an engine feature and comes after. So phase 1 builds the whole window for Object mode on the engine as it is, phase 2 adds the small engine APIs that complete it, and phase 3 holds the engine refactors, ordered by their value to the level designer.

Layout requirement, stated by the user on 2026-09-19: every area of the window must be dockable, able to change position, resizable and hideable. The mockup's arrangement (hierarchy 250 | viewport with a 250 pt bottom group | inspector 320) is the default layout of a docking system, not a fixed grid. The spec itself says "All panels resizable; widths below are defaults".

The spec's §5 lists an implementation order by screen region. This plan reorders it (§6) so that the pieces every region depends on (tokens, primitives, the docking shell, the state model) land first, the Inspector comes early, the editor stays usable after every stage, and each stage is a reviewable pull request against files that upstream changes often.

Survey of engine `develop` on 2026-09-19. Classification: **editor** (no engine change, phase 1), **small API** (a few public functions over existing state, phase 2), **engine feature** (its own proposal, phase 3).

The docking system itself (§2 first row) needs nothing from the engine: the viewport is one `MTKView` owned by the renderer, wrapped by `EditorSceneView`, and moving it between containers re-parents that view.

## 4. Engine APIs this plan needs (phase 2, except E2)

All small, each its own engine pull request, each with tests in `UntoldEngineTests`.

- **E1 Visibility.** `setEntityVisibility(entityId:isVisible:)` and `isEntityVisible(entityId:)` wrapping `RenderComponent.isVisible`, plus an optional `visibility: Bool?` field on `EntityData` written by `serializeScene` and applied by `deserializeScene` (absent means visible, so existing files are unchanged). Makes the hierarchy eye survive save and load.
- **E3 Single frame step.** `stepFrame(deltaTime:)` that runs the `gameMode` block of `runFrame` once with the given delta while `gameMode` is false. Enables the toolbar's Step button.
- **E4 Feature edges for imported meshes.** Generate `edgeIndexData` for primitives and ModelIO imports so Wireframe covers every mesh. Until then the Shading menu labels the entry "Wireframe (.untold assets)".
- **E5 Lock persistence.** Either an `editorLocked: Bool?` field on `EntityData`, or an editor sidecar file `<scene>.untoldscene.editor.json` with no engine change. Decide with the upstream maintainer when phase 2 starts (D15).
- **E2 Clip timeline (phase 3b, listed here for completeness).** `getAnimationClipDuration(entityId:clip:) -> Float?`, `getAnimationCurrentTime(entityId:) -> Float?`, `setAnimationCurrentTime(entityId:time:)` (samples the pose at that time while paused) and `stepAnimation(entityId:deltaTime:)`. Three accessors over existing internal state plus one sampling path in `AnimationSystem.update`. Only the Timeline needs it, so it goes with the Timeline.

## 5. Decisions

Each item has a recommendation; the plan is written as if the recommendation holds. Change the plan where a decision goes the other way.

- **D1 Which interaction modes ship in phase 1.** Object only. The header's mode control exists so the layout matches the mockup, but it lists Object Mode alone until Animate Mode arrives with phase 3b; Edit and Paint stay behind `EditorFeatureFlags.enableMeshEditing` and `enablePainting`, both `false`. The `InteractionMode` enum carries all four cases from the start so the badge, dock and gizmo rules are written once.
- **D2 Material editing and animation preview against the composition-only policy.** `EditorAuthoringMode.sceneCompositionOnly = true` hides animation, kinetics, scripts, LOD and batching from the Inspector and makes mesh/material editing read-only, by design ("runtime behaviour is wired in code"). Editing an object's properties in the Inspector is the point of Object mode, so the recommendation is: keep the policy for scripts, kinetics, LOD and batching; add `enableMaterialEditing`, on for the fork from phase 1; add `enableAnimationPreview` when phase 3b starts. Raise both with the upstream maintainer in the pull requests that introduce them; the stages merge with the flags off if upstream prefers.
- **D3 Panels of the default bottom group.** Keep Explore (asset packs) and Plugins (code plugins) as panels: the default bottom group is Assets · Explore · Console · Tasks · Plugins; the Timeline joins it in phase 3b. Any of them can be dragged elsewhere.
- **D4 Inspector Tag and Layer.** Deferred to phase 3c: the engine has neither, and `SceneChannel` persistence is unverified. The row is not built.
- **D5 Scene tab semantics.** Tabs list the catalog's scenes; the active one is the loaded scene; clicking another loads it through the existing unsaved-changes gate; the unsaved dot is `EditorSceneDirtyState.isDirty` on the active tab; `+` is Add New Scene. No `×` (closing a tab has no meaning with one live scene). The tooltip says "Load this scene".
- **D6 Build target.** The menu lists macOS, iOS and visionOS (what `BuildSystem.Platform` offers). It is a per-project preference saved in `UntoldEditor.json`, shown in the status bar, and does not build anything in this plan. The visionOS volume overlay waits for an engine concept.
- **D7 Shortcuts.** Q/W/E/R for Select/Move/Rotate/Scale collide with the fly keys (Q/E up/down, W/S forward/back, A/D strafe). Recommendation: fly keys act only during a right-button drag over the viewport (Unity and Unreal convention; a right click without a drag keeps selecting, as it does today through `mouseRaycast`); a plain tap of Q/W/E/R picks a tool. H hides the selection and ⌥H shows everything, since hiding is a key operation. The debug keys 1/2 and ⇧L move into the Shading menu and are unbound. Mode shortcuts: the spec's "⇥1–4" reads as Tab-number, which macOS has no idiom for; use ⌃1–⌃4 when more than one mode exists. F frames the selection. The P key, which flips `gameMode` directly today and bypasses the play-mode snapshot, is rebound to the toolbar's play toggle.
- **D8 Docking system, built in SwiftUI.** A layout tree model (splits with fractions, tab groups with panel ids) rendered by a recursive container with custom hairline dividers and the mockup's tab strips, drag-and-drop of tabs onto drop zones, persisted as versioned JSON, with the mockup as the default. `HSplitView`/`VSplitView` and `NSSplitViewController` are rejected: neither docks, both draw their own dividers and both fight the existing show/hide animation and render pause. Stage 1.3 specifies it.
- **D9 Toolbar in the title bar.** `NSWindow` with `.fullSizeContentView`, `titleVisibility = .hidden`, `isMovableByWindowBackground = true`; the toolbar is a SwiftUI row with a leading inset for the traffic lights. `NSToolbar` is rejected because the pills and the centred play cluster are not toolbar items.
- **D10 Save state, not autosave.** The status bar shows "● Unsaved changes" (orange) or "Saved HH:MM" from the dirty flag and the last successful save; autosave does not exist and is its own feature.
- **D11 Stats overlay default.** On by default in the compact two-line form of the mockup (`62 fps · 4.2 ms` / `1,248 tris · 3 draw calls`); the View menu still toggles it and the advanced form stays opt-in.
- **D12 Menus with subtitles and toggles.** The mode menu (subtitle + shortcut per item) and the snap menu (steppers and toggles) are custom popovers (`EditorPopupMenu`); plain SwiftUI `Menu` elsewhere. `NSMenuItem.subtitle` needs macOS 14.4 and is not reachable from SwiftUI `Menu`.
- **D13 Icons.** SF Symbols throughout (Appendix B); no custom icon assets.
- **D14 Explore mode.** Toolbar and status bar are global and show in both experience modes (play cluster disabled in explore). Entering explore mode collapses the layout to the viewport, as Focus Viewport does, and switching back to edit restores the saved layout.
- **D15 Persistence of eye and lock.** Session-only in phase 1. Visibility persists with E1, lock with E5, both in phase 2.
- **D16 Branch base.** Each stage branches from `upstream/develop`, is reviewed as a pull request on `untoldengine/UntoldEditor`, and the fork takes it back through its usual `sync/upstream_develop_MMDD` pull request. The alternative used for Code Components (fork branch first, cherry-picked `-upstream` branch) doubles the conflict work on `EditorView.swift` and `InspectorView.swift`, where the fork-only Splat Twin code sits inside the regions being restyled. Fork-only sections get restyled at sync time.
- **D17 Floating panels.** "Dockable" implies undocking. Recommendation: in phase 1 a tab's context menu offers Float, which opens the panel in its own `NSWindow` (an `NSHostingView` with the same shared session objects), and the floating window's title bar offers Dock to return it to its last group. Dragging a tab out of the window to float it is polish for stage 1.10. The viewport panel does not float in phase 1 (D18).
- **D18 What is a panel.** Panels: Hierarchy, Viewport, Inspector, Assets, Explore, Console, Tasks, Plugins, and the Timeline from phase 3b. Fixed chrome, not panels: the toolbar, the status bar, and the scene tab strip and tool header, which belong to the viewport panel. The viewport panel can be moved and resized but not closed (there is one, and closing it leaves nothing to edit) and not floated in phase 1, because moving the renderer's `MTKView` to another window is unverified. Environment and Effects stay inside the contextual Inspector panel as today; making them panels of their own is possible later without changing the docking system.

## 6. Delivery in three phases

Every stage leaves the editor usable, builds with `/usr/bin/swift build`, passes `swift test` (the editor suite has one failure that predates this work, `CreateProjectViewTests…resultProjectPathIsNilByDefault`, on Xcode 27) and is lint-clean for its own files. "Person" in the checks means a hand check in the running editor, since macOS blocks UI scripting on this machine. Sizes: S under a day of work, M a few days, L a week or more.

### Phase 1. Object mode on today's engine (editor-only)

The whole window of the mockup for placing objects, moving around them and editing their properties, with no engine change, on a docking layout. The header's mode control shows Object Mode only (D1); the Timeline panel, Edit mode and Animate mode do not appear yet. This phase is a releasable editor version on its own.

#### Stage 1.0. Split the big files and lay the sources out by scene (M)

Goal: cut merge conflicts and type-checker time before touching layout, and give the sources the layout the user asked for on 2026-09-19: **one folder per scene** (an area or panel of the editor, which may hold several views), **one View per file** (a view's own `ViewModifier` is the only thing allowed to share its file), and a view's extensions and helpers in sibling files of its folder. Pure moves, no behaviour change; the only textual change is that `private` becomes internal where a type or member now crosses a file boundary.

- `EditorView.swift` (3,088 lines, 38 upstream commits since June, body already "at the limit of what the type checker resolves") becomes `Editor/Window/EditorView.swift` (state, init, body) plus extensions by concern: `+Viewport`, `+Layout`, `+RightPanel`, `+BottomDock`, `+DragDrop`, `+SceneIO`, `+Explore`, `+Project`, `+Entities`, `+PlayMode`, `+DemoScenes`, `+SceneAuthored`, `+QuickPreview`; its two helper views get their own files.
- `InspectorView.swift` (2,308 lines) becomes `Editor/Inspector/InspectorView.swift` plus `InspectorView+Components`, `ComponentOptions` (the registry and free functions), one file per component editor and per helper view.
- `AssetBrowserView.swift` (3,034 lines) becomes `Editor/AssetBrowser/AssetBrowserView.swift` (state and body) plus twelve extensions (`+DirectoryTree`, `+Shelves`, `+Contents`, `+Import`, `+RuntimeExport`, `+TilesExport`, `+Loading`, `+Selection`, `+Placement`, `+StreamModels`, `+Gaussian`, `+SceneLoading`), `AssetFileHelpers`, `AssetExportRequests`, `AssetModel` and the two helper views.
- Every other multi-view file is split the same way (environment effect editors, explore gallery cards, tasks rows, viewport helpers, numeric input fields, plugin inspector pieces).
- Folders: `Editor/Window`, `Viewport`, `Hierarchy`, `Inspector`, `AssetBrowser`, `AssetPacks`, `Console`, `Tasks`, `Environment`, `Explore`, `Gaussian`, `Project` (controller, scene catalog, dirty state, switch gate, undo, selection), `Shared` (theme, text fields, loading indicators), `CreateProject` (was `Build/`). `Components/` keeps its name; its multi-view files are split. `TransformManipulationToolbar` stays: tests use it.

Checks: suite green; declaration lists identical before and after with access stripped; swiftformat findings identical to the pristine tree (the installed 0.62 reports rules the pinned 0.60.1 lacks); every build warning traced to a line that existed before. **Done 2026-09-19: commit `99cd93f` on branch `feature/ui_redesign` in worktree `UntoldEditor-uiredesign`, after the user tried the split editor by hand. Not pushed; the pull request waits until more stages are on the branch (§7).**

#### Stage 1.1. Tokens and control primitives (S)

Goal: the whole editor takes the mockup palette without layout changes.

- `EditorScheme.swift`: re-value existing tokens to the spec (§3 of the spec), add `editorChromeBackground`, `editorViewportHeader`, `editorTabStrip`, `editorBarDark`, `editorControlFill`, `editorControlActive`, `editorTextDisabled`, axis (`editorAxisX/Y/Z`), navigation (`editorNavX/Y/Z`), mode (`editorModeEdit/Animate/Paint`) and the scrim. Keep every existing name so no call site changes. `AppDelegate` window background reads the token instead of the literal.
- New `Editor/Controls/`: `EditorPillGroup` (grouped buttons, black 25 % fill, radius 7), `EditorSegmented` (World/Local, grid/list), `EditorDropdownLabel` (chevron label for `Menu`), `EditorPopupMenu` (D12), `EditorSearchField` (wraps `ExplicitClickTextField`, placeholder, trailing hint), `EditorFilterChip`, `EditorIconButton`, `EditorSplitDivider` (the hairline divider the docking system drags).
- Typography constants (`EditorType`): body 12, title 12 semibold, hint 11, mono 11.

Tests: a token table test (every token the spec names exists), primitive state tests through `Mirror` as the existing view tests do. Person: nothing looks broken.

Done 2026-09-19, commit `0abc781` on `feature/ui_redesign`: tokens re-valued with the spec's hex values behind a private `Color(hex:)` helper, extra spec colors added (selected-row text, console error and warning text, error row background, badge red, mode dot for Object), `editorSecondaryAccent` and `editorInfo` mapped to the palette blue, `EditorDisclosureStyle` in its own file, `EditorType` with fonts and radii, ten controls one per file under `Editor/Shared/Controls/`. The state logic of the controls is static functions tested directly (`EditorControlsTests`) instead of `Mirror`, which reads only stored properties; the token values are checked by resolving each `Color` to sRGB (`EditorSchemeTests`).

#### Stage 1.2. Toolbar, status bar, window chrome (M)

Goal: the global frame of the mockup.

- Window: D9. Toolbar row 48 pt (`EditorToolbarView`): project chip (`EditorAssetBasePath.shared.projectName`, `AppDelegate.editorVersion`), Undo/Redo/History pill (`EditorUndoManager` gains `undoHistory: [String]` and `redoHistory` from the command names; History is a popover listing them, click to undo to that point), Play/Pause/Step pill centred, build target `Menu` (D6), search field (opens the palette from stage 1.9; until then it filters nothing and says so in its tooltip).
- `EditorPlayState` model: `.editing`, `.playing`, `.paused`. Play from editing snapshots and sets `gameMode = true` (existing `setEditorPlayMode`); Play while playing or paused stops and restores; Pause sets `gameMode = false` keeping the snapshot; Step is drawn disabled with the tooltip "needs an engine frame step" until E3 (phase 2). #### Stage 1.3. Docking layout shell (L)

Goal: every panel dockable anywhere, movable, resizable and hideable, with the mockup as the default layout. Built before the panels are restyled because every panel's header becomes a tab strip of this system.

| --- | --- |

| The layout JSON changes shape between versions. | Versioned key with fallback to the default layout. |
| SwiftUI overlays over the Metal view cost frames if they invalidate per frame. | Passive overlays are `allowsHitTesting(false)`; the gizmo and selection rectangle tick at 30 Hz from one timer, the stats store at 5 Hz; nothing publishes from the render loop (the Inspector refresh throttle exists for this reason). |
| Divider drags stutter against the live viewport. | The render loop holds during a divider drag, as during a window resize. |
| Full-size content view: the toolbar row sits under the traffic lights and the window loses its drag region. | Leading inset for the traffic lights; `isMovableByWindowBackground`; verify on a notched display and with the sidebar collapsed. |
| Wireframe draws nothing for primitives and USDZ imports. | Label the entry; E4 in phase 2. |
| Stats are zeros when the engine is built without `ENGINE_STATS_ENABLED`. | Debug builds and the bundle script define it; the status bar shows "—" instead of 0 when the snapshot is empty. |
| Scene tabs suggest several open documents. | D5 tooltips and no `×`; the strip is a switcher. |
| Two lock icons with two meanings (hierarchy lock vs Inspector pin). | Pin symbol in the Inspector (stage 1.5). |
| The composition-only policy contradicts the Material section and, later, the Timeline. | D2 flags, raised with upstream at those stages; the stages merge with the flags off. |

| A one-entry mode control looks odd. | It is the mockup's control with the entries it can honour; Animate arrives in 3b. Alternative if preferred: draw it as a static pill until then. |

## 9. Acceptance

**Phase 1** is accepted when:

1. Screens 01, 03 and 04 are reproduced in the running editor at 1440 × 861 and 1920 × 1080 as the default layout; screen 02 with the Assets or Console panel in place of the Timeline; screens 05 and 06 are out of scope until phase 3.
2. Every panel of D18 can be dragged to any zone of any group and to the window edges, resized by its dividers, closed and reopened from the Window menu, and floated and docked back (viewport excepted); the layout survives a relaunch; Reset Layout returns to the mockup; the viewport keeps rendering through every move and resize.
3. A level designer can place an asset from the grid or list, move, rotate and scale it with snapping in world and local space, hide and lock it from the hierarchy, frame it, and change its name, transform, mesh, shadows and material from the Inspector, with undo for each change.
4. Every feature that existed before (scene save/load/rename, import/export/cook flows, drag and drop, play/stop with restore, undo/redo, ⌘1/2/3/⌘F, plugins panel, code plugins in the Inspector, Splat Twin section, explore mode with the demo gallery) still works.
5. No frame-rate regression with all overlays on, measured with the engine stats in the status bar on the sample project.
6. Editor suite green except the pre-existing failure; each stage adds the tests it lists.
7. `UI_Changes.md` describes the new layout and docking, and Appendix C matches the shipped shortcuts.

**Phase 2** is accepted when hidden and locked entities come back hidden and locked after save and load, Wireframe shows every mesh, and Step advances exactly one frame while paused.

**Phase 3** items carry their own acceptance criteria in their own proposals.
